# 핵심 변수 설명

이 문서는 수업 당시 최종 노트북의 변수와 포트폴리오 정리본의 계산을 설명합니다. 원본 발표자료에서 간단히 설명한 식과 코드의 차이를 함께 기록합니다.

## 정리본의 열 이름

| 수업 당시 이름 | 정리본 이름 |
|---|---|
| `종목`, `date` | `stock`, `date` |
| `뉴스건수`, `검색량` | `news_count`, `search_index` |
| `종가`, `등락률`, `거래량` | `close`, `return_pct`, `volume` |
| `개인(순매수)` | `retail_net_buy` |
| `이슈강도` | `issue_intensity` |
| `next_trade_date` | `next_trade_date` |
| `등락률_next`, `거래량_log_next` | `next_return_pct`, `next_log_volume` |
| `등락률_abs`, `거래량_log` | `abs_return_pct`, `log_volume` |

정리본은 `next_trade_date`를 정렬된 실제 거래일 목록에서 이슈 날짜보다 **엄격히 뒤인 첫 날짜**로 계산합니다. 이는 아래 원본의 `shift`·`merge_asof` 연결 의도를 직접 표현한 방식입니다.

## 1. 원본 변수

| 변수 | 의미 | 해석할 때 확인할 점 |
|---|---|---|
| `date` | 뉴스·검색 또는 주식 데이터가 발생한 날짜 | 거래일과 달력 날짜를 구분 |
| `종목` | 분석할 주식 종목명 | 날짜와 함께 병합 기준으로 사용 |
| `뉴스건수` | 해당 종목과 관련해 수집한 일별 기사 건수 | 기사량은 호재·악재 방향이나 감정을 직접 나타내지 않음 |
| `검색량` | 네이버 데이터랩의 종목별 검색량 지수 | 실제 검색 횟수와 구분해야 함 |
| `종가` | 해당 거래일의 장 마감 가격 | 휴장일 행에서는 앞선 값을 이어 사용 |
| `등락률` | 전 거래일 대비 가격 변동률(%) | 다음 거래일 값과 연결할 때 단위를 유지 |
| `거래량` | 해당 거래일에 거래된 주식 수 | 개인투자자만의 거래량을 뜻하지 않음 |
| `개인(순매수)` | 개인 매수 수량에서 개인 매도 수량을 뺀 값 | 음수는 순매도이며, 주가 상승 여부와 별개의 값 |

## 2. 이슈강도

최종 코드의 실제 식은 다음과 같습니다.

```python
뉴스_log = np.log1p(뉴스건수)
검색_log = np.log1p(검색량)
이슈강도 = 뉴스_log + 검색_log
```

`log1p(x)`는 `log(1 + x)`입니다. 0을 포함한 데이터에 적용하면서 큰 값의 차이를 압축합니다. 두 로그값을 더해 뉴스와 검색 관심이 함께 커지는 날짜를 찾는 데 사용했습니다.

발표자료에는 ‘뉴스 기사 건수 + 검색량’으로 요약되어 있지만, 코드에서는 **각각 로그 변환한 뒤 더합니다**. 이 값을 투자자의 FOMO 확률이나 심리 강도의 절대적인 측정값으로 해석할 수는 없습니다. 로그 변환만으로 서로 다른 자료의 척도가 완전히 같아지는 것도 아닙니다.

## 3. 다음 거래일 연결 변수

### `next_trade_date`

각 이슈 날짜보다 뒤에 있는 다음 실제 거래일입니다. 종목별 주식 데이터에서 거래일 목록을 만들고, 각 거래일의 다음 거래일을 `shift(-1)`로 구합니다. 이후 `merge_asof`로 이슈 날짜 당일 또는 그 이전의 마지막 거래일을 찾고, 그 거래일의 다음 거래일을 붙입니다.

- 금요일 이슈 → 다음 거래일인 월요일
- 토요일·일요일 이슈 → 다음 거래일인 월요일
- 월요일도 휴장일인 경우 → 그다음 실제 거래일

이 설명은 거래일 목록에 누락이 없다는 조건을 전제로 합니다. 원본 데이터의 마지막 거래일 이후에 해당하는 반응은 관찰할 수 없어 결측치가 남습니다.

### `등락률_next`, `거래량_log_next`

| 변수 | 실제 값 |
|---|---|
| `등락률_next` | 같은 종목의 `next_trade_date`에 해당하는 `등락률` |
| `거래량_log_next` | 같은 종목의 `next_trade_date`에 해당하는 `log(1 + 거래량)` |

토요일·일요일의 이슈 날짜와 값은 유지하면서 각각 다음 거래일 반응을 붙입니다. 주말 데이터를 하나로 합산하는 처리는 아닙니다. 여러 이슈 날짜가 같은 반응을 공유한다는 점을 고려해 해석해야 합니다.

## 4. 다른 파생변수

| 변수 | 식 또는 계산 방식 | 사용 목적 |
|---|---|---|
| `등락률_abs` | `abs(등락률)` | 상승·하락 방향을 제외한 당일 움직임 크기 비교 |
| `거래량_log` | `log(1 + 거래량)` | 큰 거래량 값의 차이를 압축 |
| `수익률_변동성` | 선택한 이슈 주변 구간의 등락률 표준편차 | 이벤트 주변 가격 변동 크기 비교 |
| `거래량_스파이크` | 정리본: 이벤트 거래일 거래량 ÷ 직전 최대 20거래일 평균 거래량 | 과거 기준에 비해 거래량이 얼마나 큰지 비교 |
| `이슈_민감도` | 위 두 반응값을 각각 표준화한 `ret_z + vol_z` | 반응을 종합해 비교하기 위한 탐색용 점수 |

원본 일부 주석은 ‘거래일’이라고 적혀 있지만 주말 포함 데이터의 행을 기준으로 구간을 자릅니다. 정리본은 이를 실제 거래일 기준으로 수정했습니다. 이슈가 휴장일이면 그다음 거래일을 이벤트 거래일로 잡고, 그 전후 최대 7거래일을 비교합니다. 구간 끝에서 관측치가 부족한 경우 실제 행 수를 결과에 기록합니다.

## 5. 시계열 그림의 정규화와 SPK 표시

검색량·뉴스 건수·개인 순매수·종가를 각각 종목 내 최솟값과 최댓값을 기준으로 0~1로 바꾸어 겹쳐 그렸습니다. 이 때문에 네 선의 절대적인 금액·수량을 직접 비교할 수는 없습니다.

최종 시계열 그림에서는 다음과 같이 표시 대상을 좁힙니다.

1. 검색량 또는 종가가 20개 행 이동평균에 이동표준편차의 2배를 더한 기준보다 높은지 판별합니다. 최소 5개 관측치를 사용합니다.
2. 둘 중 하나라도 기준을 넘으면 급증 후보로 잡습니다.
3. 급증 후보 안에서 검색량이 상위 10%에 해당하는 날짜만 강조 표시합니다.

이는 정해 둔 기준으로 관심 구간을 표시하는 규칙입니다. FOMO 발생을 확정하는 분류 결과는 아닙니다.

위 SPK 설명은 `assets/samsung_flow.png`의 수업 당시 그림에 해당합니다. 정리본의 `results/samsung_timeline.png`는 같은 네 시계열과 실제 거래일 등락률을 별도 축으로 보여주며, 특정 기사 기록 날짜를 점선으로 표시합니다.

## 6. 정리본의 FOMO 지표와 급증 반응

- `FOMO_Index`: 뉴스·검색의 달력일 표준편차, 실제 개인 순매수의 거래일 표준편차, 검색량과 순매수의 0~3거래일 시차별 피어슨 상관 중 최댓값을 각각 10종목 간 0~1로 바꾸고 평균한 값입니다. 시차 상관은 실제 거래일로 맞춘 `search[t]`와 `net_buy[t+lag]`를 비교합니다.
- 검색 급증: 전체 기간 검색 지수의 평균 + 표준편차 2배 초과.
- 순매수 급증: 실제 거래일 순매수의 평균 + 표준편차 2배 초과.
- 반응 관찰 창: 검색 발생일 당일 또는 이후의 첫 거래일을 0으로 두고, 그다음 3거래일까지 관찰합니다. 주말 검색이면 월요일이 0에 해당합니다.
- `matched`: 창 안에 반응이 있으면 최초 반응 한 번만 기록합니다. 같은 날 연결도 포함하므로 시간적 선후·인과관계를 뜻하지 않습니다.
- `unmatched`: 관찰 창 전체가 존재하면서 반응이 없는 경우입니다.
- `censored`: 관찰 창 끝까지 볼 수 없고 반응도 관측되지 않은 경우입니다.

각 종목에서 `search_events = matched + unmatched + censored`가 성립합니다. 서로 다른 검색 이벤트가 동일한 거래일 반응을 공유할 수 있으며, 지표의 척도·선택 시차·급증 임계값은 현재 표본에 의존합니다.
