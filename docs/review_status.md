# 코드 검토와 재현 범위

원본 수업 과제의 구현 상태와 2026-10-15 포트폴리오 정리 과정의 수정 사항을 기록합니다. 수업 당시 참고 코드(`archive/`)와 이번 정리본(`src/fomo_eda.py`)을 구분합니다. 원본 로컬 파일은 보존했습니다.

## 정리본의 수정·검증 결과

| 항목 | 정리본의 처리 |
|---|---|
| 순매수 열 | 정확한 `개인(순매수)`를 추출한 `retail_net_buy` 사용, 매수−매도와 일치 검사 |
| 시차 비교 | `corr(search[t], net_buy[t+lag])`의 피어슨 상관계수, 0~3거래일의 방향을 명시 |
| FOMO 지표 | 수정한 네 특징을 10종목 사이에서 정규화해 동일 가중 평균, 탐색용 상대 지표로 설명 |
| 검색 급증 반응 | 검색 이벤트 한 건마다 최초 반응을 한 번만 집계, 관찰 창이 부족하면 별도 `censored` 처리 |
| 주말 반응 | 원래 이슈 날짜를 유지하며 다음 실제 거래일에 연결, 데이터 끝부분의 미래 반응은 결측 유지 |
| 반응 상관계수 | 같은 거래일에 연결된 이슈강도를 평균해 시장 반응 한 건씩 비교 |
| 이벤트 구간 | 실제 거래일 기준 전후 최대 7개 관측치, 이전 최대 20거래일 거래량 평균 |
| 군집 수 평가 | 최종 군집화와 동일한 두 표준화 변수에서 K=2~6 평가 |
| 재실행 | 포함한 CSV에서 전체 정리본 실행 완료, PNG 3개와 결과 CSV·환경 요약 생성 |
| 테스트 | 주말·휴장일·기간 끝, 반응 중복·미관찰, 시차 방향·정규화, 중복 키 등 7개 통과 |

재실행에서는 군집 수 K=2의 실루엣 점수(약 0.499)가 K=3(약 0.392)보다 높았습니다. K=3은 수업 당시 비교 구성을 남긴 기술적 선택이며 최적값으로 주장하지 않습니다. NAVER의 이슈 날짜가 자료 끝부분에 있어 전후 관측 구간이 9거래일로 짧은 점도 군집 해석의 한계입니다.

아래 2~4절은 **원본에서 발견한 문제와 변경 이유**에 대한 기록입니다. 해당 문제가 정리본에도 그대로 남아 있다는 의미는 아닙니다.

## 1. 확인한 자료

- 최종 분석 노트북: `탐색적 데이터 분서 (이슈와 주식) EDA_code_최종.ipynb`
- 별도 실험 노트북: `탐데 팀플 데이터/갱니/test.1.ipynb`
- FOMO 주제 제안서, 중간 현황 보고서, 최종 발표자료, 발표 대본
- 주제 제안, 협업·AI 활용 범위, 어려움과 회고에 대한 작성자의 설명

최종 노트북에는 수업 당시 실행 결과가 저장되어 있습니다. 원본의 저장된 결과를 읽고 정리본의 계산을 새로 실행했습니다. 원본 두 노트북을 수정·재실행한 것으로 설명하지 않습니다.

## 2. 최종 분석과 별도 FOMO 실험의 차이

| 구분 | 최종 분석 노트북 | 별도 실험 `test.1.ipynb` |
|---|---|---|
| 분석 종목 | 10개 종목 | 중간에 네이버를 제외한 9개 종목 |
| 관심 지표 | 로그 뉴스 건수 + 로그 검색량인 `이슈강도` | 네 가지 종목별 특징을 결합한 `FOMO_Index` |
| 날짜 연결 | 주말 이슈를 `next_trade_date`와 연결하는 처리 포함 | 급증 반응 집계에서 달력 날짜에 1~3일을 더해 일치 여부 계산 |
| 결과 사용 | 시계열·관계 탐색의 설명 근거 | 계산 문제를 보완한 뒤 결과를 다시 검증할 필요가 있는 실험 |

이 두 노트북의 지표와 결과를 같은 최종 성과로 합쳐 설명하지 않았습니다.

## 3. 별도 실험의 FOMO 지표

의도한 구성은 다음과 같습니다.

```python
features = [뉴스_STD, 검색량_STD, 순매수_STD, LagCorr]
scaled = MinMaxScaler().fit_transform(features_by_stock)
FOMO_Index = scaled.mean(axis=1)
```

뉴스·검색·매매 변동성은 표준편차이며, `LagCorr`는 평균을 뺀 두 시계열에 `np.correlate(..., mode="full")`를 적용한 뒤 최댓값을 취한 값입니다. 각 특징을 9개 종목 사이에서 0~1로 바꾸고 같은 가중치로 평균했습니다.

### 확인된 문제

1. **순매수 열 선택이 모호함**
   - 코드가 열 이름에 `개인`이 있고 `순` 또는 `수`가 포함되는 첫 열을 고릅니다.
   - 이 조건에는 `개인(매수)`도 들어가므로 의도한 `개인(순매수)` 대신 매수 열이 선택될 수 있습니다.
   - 열을 정확한 이름으로 선택하고 입력값을 확인한 뒤 지표를 다시 계산해야 합니다.

2. **`LagCorr`를 일반적인 상관계수로 설명할 수 없음**
   - 현재 값은 -1~1 범위로 정규화된 피어슨 상관계수가 아닙니다.
   - 모든 양·음의 시차 중 최댓값을 골라 검색이 매수보다 먼저였다는 방향도 보장하지 않습니다.
   - 관심 있는 시차와 방향을 먼저 정의하고 비교값을 정규화해 계산할 필요가 있습니다.

3. **급증 반응의 중복 집계**
   - 검색 급증 뒤 같은 날, 1일 뒤, 2일 뒤, 3일 뒤의 매매 급증을 각각 세어 더합니다.
   - 하나의 검색 급증이 여러 날의 반응과 연결되면 중복 계산될 수 있습니다.
   - 저장된 결과에서 ‘반응 없음’이 에코프로 -1, 카카오 -3 등 음수로 나와, 이 값을 반응률이나 적중률로 사용할 수 없습니다.
   - 검색 이벤트마다 정해진 구간 안에 반응이 있었는지 한 번만 판단하거나, 최초 반응까지의 지연을 계산하도록 집계 단위를 정해야 합니다.

4. **달력일과 거래일 차이**
   - 실험 코드는 날짜에 달력일 1~3일을 더합니다.
   - 주말을 낀 경우와 거래일 기준 반응을 혼동하지 않도록 최종 분석의 거래일 연결 방식과 기준을 맞춰야 합니다.

원본 실험의 종목 순위·반응 비율은 검증된 성과로 사용하지 않습니다. 정리본의 계산 결과도 실제 심리나 미래 예측력을 검증한 지표와 구분합니다. 서로 다른 검색 이벤트가 같은 매매 급증과 연결될 수 있어, 수정한 집계 역시 인과 효과나 독립적인 사건 수를 뜻하지 않습니다.

## 4. 최종 노트북에서 추가 확인할 사항

- **이벤트 구간:** ‘±7거래일’, ‘직전 20일’ 같은 주석과 달리 주말이 포함된 데이터에서 행 단위로 구간을 선택합니다. 실제 거래일만 사용할지 달력일을 사용할지 정한 뒤 설명과 계산을 맞춰야 합니다.
- **군집 수 평가:** 엘보우·실루엣 계산은 앞서 만든 `X_scaled`를, 최종 군집화는 `ret_z`, `vol_z` 두 열을 사용합니다. 같은 입력으로 평가를 다시 하지 않은 상태에서 ‘통계적으로 최적의 K=3’이라고 설명하지 않았습니다.
- **휴장일 보정:** 병합 후 값이 없는 거래량·등락률 등을 0으로 채웁니다. 실제 휴장일과 거래일의 수집 누락을 구분하는 확인이 필요합니다.
- **동일 반응의 반복 연결:** 금요일·주말 이슈가 같은 다음 거래일 반응을 공유합니다. 상관분석과 사건 수를 해석할 때 같은 결과값의 반복 사용을 고려해야 합니다.
- **관심과 심리의 구분:** 뉴스량·검색량은 관심의 대리변수입니다. 개인 심리 측정이나 FOMO의 인과 효과를 입증한 것으로 설명하지 않습니다.
- **대표 뉴스 해석:** 뉴스의 종목 관련성, 보도 시각과 장중·장후 여부를 추가로 대조해야 합니다. 하루의 대표 기사만으로 해당 거래일 가격 변동 원인을 정하지 않습니다.

## 5. 재현 범위와 남아 있는 한계

1. 개인 PC 경로 없이 저장소의 CSV에서 실행할 수 있습니다. 환경 버전과 입력 해시는 `results/summary.json`에 남겼습니다.
2. 초기 데이터 수집 코드와 검색 조건 일부는 확인되지 않아 외부 자료 수집의 전체 자동 재현은 포함하지 않습니다.
3. 거래일은 수집된 날짜 목록 기준이며 별도의 공식 거래소 달력과 대조하지 않았습니다.
4. 급증 임계값·정규화·최대 상관 시차는 같은 전체 기간에서 정한 사후 분석 기준입니다. 시간 순서로 나눈 검증이나 예측 성능 평가는 수행하지 않았습니다.
5. 이슈강도 평균과 다음 거래일 반응의 상관은 추세·시장·업종·자기상관 등을 통제하지 않은 기술적 비교입니다.

이번 정리와 코드 보완은 Codex를 활용해 진행한 과제 이후의 작업입니다. 팀원이 수업 당시 제안한 날짜 연결 아이디어와 작성자가 직접 데이터를 수집하고 코드를 실행했던 경험에 대한 기여 설명은 구분해 보존했습니다.
